# MathCards

Десктопное приложение для изучения математического анализа на русском языке. Карточки с форматированным текстом, LaTeX и фотографиями; ручное повторение выбранных карточек; SQLite и локальные резервные копии. Сервер, учётная запись и интернет во время использования не нужны.

## Быстрый запуск на macOS или Windows

Нужен Node.js **24 LTS** и npm. Для разработки подходят также Node.js 22.16+ (локальные проверки выполнены на 22.23.4). Первый `npm ci`/запуск загружает зависимости и Electron из интернета. После установки приложение работает автономно.

```bash
npm ci
npm run dev
```

`npm run dev` запускает Vite и настоящее окно Electron с SQLite. Изменения React подхватываются автоматически; после изменений `electron/` перезапустите команду. `npm run dev:ui` запускает только Vite: обычному браузеру намеренно не предоставляется доступ к SQLite, поэтому полноценный сценарий выполняйте через Electron.

```bash
npm run typecheck  # TypeScript strict
npm test           # Vitest: SQLite, бизнес-логика, архивы
npm run build      # frontend + main + sandbox preload
npm start          # запуск production-сборки локально
npm run test:e2e   # сборка + Playwright в настоящем Electron
npm run pack:mac   # локальная .app для macOS, без подписи
```

Не открывайте две копии приложения с одним каталогом данных: приложение использует single-instance lock.

## Получение Windows .exe

### GitHub Actions — рекомендуемый способ

1. Откройте приватный репозиторий [KingArthurTheGreat/MathCards](https://github.com/KingArthurTheGreat/MathCards). Исходники и workflow находятся в ветке `main`.
2. Откройте **Actions → Windows installer → Run workflow**. Workflow также запускается при push в `main`/`master`, тегах `v*` и pull request.
3. Дождитесь успешного завершения: установка зависимостей, TypeScript, Vitest, production-сборка, Electron E2E и упаковка.
4. Внизу страницы запуска скачайте **Artifacts → MathCards-Windows-x64-unsigned** (или `signed` для подписанной сборки) и распакуйте архив.
5. Запустите `MathCards-Setup-1.1.0.exe`. Node.js конечному пользователю не нужен.

В тот же Artifact входит `MathCards-Portable-1.1.0.exe`. Portable не требует установки, но данные хранит в пользовательском профиле, а не рядом с EXE. Артефакты хранятся 30 дней; затем сохраните их отдельно или повторите workflow.

### Локально на Windows 10/11 x64

```powershell
npm ci
npm run typecheck
npm test
npm run dist:win
```

Результаты находятся в `release/`. Настроен NSIS с русским интерфейсом, выбором каталога и ярлыком. При обновлении не меняйте `appId` и имя приложения. `deleteAppDataOnUninstall: false` сохраняет пользовательские карточки даже при удалении программы.

**Windows-сборка в текущем окружении macOS не выполнялась. Готовый Windows EXE не заявляется как проверенный.** Статус последнего фактически выполненного Windows workflow указан в `VERIFICATION.md`. Windows 10/11 требуют отдельного прогона установщика, обновления и удаления на реальной системе/VM. CI проверяет приложение на Windows runner, а не все версии Windows.

## Что работает

- Создание, переименование, описание и подтверждаемое удаление наборов.
- Создание и редактирование двух сторон; дублирование, удаление, массовое перемещение карточек.
- Типы «Определение», «Теорема», «Доказательство», «Другое»; теги, поиск по названию, фильтры.
- TipTap: жирный/курсив, заголовки, списки, отмена/повтор; предпросмотр обеих сторон.
- Строчные и блочные формулы KaTeX, LaTeX-редактор с предпросмотром и панелью символов. Для редактирования нажмите на существующую формулу. Ввод `$...$` и `$$...$$` также поддерживается расширением TipTap.
- PNG/JPEG/WebP из файла, буфера Ctrl+V (Cmd+V на Mac), внешнего drag-and-drop. До 20 МБ на изображение.
- Фото копируется в приложение; исходный файл можно переместить или удалить. Можно оставить сторону только с фотографией.
- Свободное изменение ширины фото за любой из четырёх углов (10–100% с шагом 0,1%), сохранение пропорций и размера после перезапуска. Доступны также предустановки 25/50/75/100% и управление фокусированным углом клавишами стрелок (Shift — шаг 10%). В предпросмотре и изучении нажатие открывает увеличенное изображение.
- Выбор галочками, выделение видимых результатов, снятие выделения, диапазон по номерам и Shift+клик. Выбор сохраняется при фильтрации; счётчик сообщает о скрытых выбранных карточках.
- Подборки содержат ссылки, а не копии. Можно сохранить выбор в новую или добавить в существующую подборку без дублей, переименовать подборку, убрать из неё выбранные карточки или удалить только подборку.
- Изучение только выбранных карточек, по порядку или с перемешиванием; прогресс, обе стороны, анимация, внутренний скролл длинных доказательств.
- Результаты «Не знаю», «Сложно», «Знаю» сохраняются **после каждой оценки**. Повторная оценка в одной сессии заменяет прежнюю и не увеличивает счётчик.
- Статистика сессии и повтор всех/сложных/неизвестных; общая статистика за 14 дней и история. Пауза и продолжение незавершённой сессии с первой неоценённой карточки после перезапуска.
- Интервальные повторения SM-2: дата следующего повторения в списке, прогноз интервала на кнопках оценки, вкладки «Пора повторить», «Запланированные» и «Сложные и неизвестные».
- Светлая, тёмная и системная темы; последние открытые наборы; onboarding с возможностью отказаться от примеров.
- Семь корректных учебных примеров: определения пределов, замечательный предел, непрерывность, Больцано — Коши и Вейерштрасс.
- Экспорт отдельного набора или всей библиотеки, импорт ZIP с фотографиями, формулами, тегами, подборками и историей.

## Основной сценарий

1. Создайте набор «Экзамен по матану».
2. Нажмите «Добавить карточку», укажите название, текст лицевой стороны.
3. В обратной стороне введите формулировку; «Формула» открывает редактор LaTeX.
4. Скопируйте изображение в буфер, поставьте курсор в нужный редактор, нажмите Ctrl+V. Дождитесь загрузки.
5. Нажмите «Предпросмотр», затем «Сохранить». При закрытии несохранённой карточки есть предупреждение.
6. Добавьте остальные карточки. После полного закрытия и повторного запуска данные сохраняются.
7. Выберите три карточки галочками, при необходимости включите «Перемешать» и нажмите «Изучать выбранные».
8. Переверните карточку, оцените знание. В конце повторите неизвестные.
9. Экспортируйте набор кнопкой со стрелкой вниз в его заголовке. Импорт доступен в «Настройки».

| Клавиша   | В режиме изучения                            |
| --------- | -------------------------------------------- |
| Space     | Показать/скрыть ответ                        |
| ← / →     | Предыдущая / следующая, без оценки           |
| 1 / 2 / 3 | Не знаю / сложно / знаю, после показа ответа |
| Esc       | Завершить и показать результаты              |

Горячие клавиши игнорируются в полях ввода, редактируемом контенте и открытых диалогах. Кнопка «Завершить» показывает результаты и позволяет вернуться в библиотеку. Пропущенные карточки не считаются оценёнными.

## Архитектура

```text
electron/
  main.ts          окно, протоколы app/media, безопасный IPC, native dialogs
  preload.ts       ограниченный типизированный bridge
  database.ts      SQLite, миграция v1, транзакции, файлы изображений
  backup.ts        ZIP-манифест, SHA-256, валидация, импорт с remap ID
  demo.ts          отделённые демонстрационные наборы
shared/
  model.ts         общий контракт данных и IPC
  validation.ts    схемы Zod и проверка документов
  study.ts         выбор диапазона, shuffle, повторение
  scheduler.ts     SM-2, дневное объединение оценок, даты повторения
  image-size.ts    геометрия пропорционального изменения размера
src/
  components/      редактор, KaTeX-контент, диалоги, форма набора
  pages/           библиотека, домашняя, редактор, изучение, настройки, статистика
  hooks/           React store, загрузка снимка, ошибки, уведомления, тема
  styles.css       Tailwind CSS 4 и стили компонентов
scripts/           сборка Electron, запуск dev, Electron E2E
 tests/            Vitest интеграционные тесты на настоящей SQLite
.github/workflows/ Windows CI и installer artifacts
```

SQLite используется через встроенный `node:sqlite` главного процесса Electron. Это настоящая файловая SQLite без отдельного ABI-модуля и сборки нативного аддона под каждую платформу. В Node 22 API помечен experimental; API и Electron зафиксированы lock-файлом и проверяются интеграционными тестами. Renderer не получает Node API.

Таблицы: `decks`, `cards`, `tags`, `card_tags`, `images`, `card_images`, `collections`, `collection_cards`, `sessions`, `session_cards`, `results`, `settings`, `review_state`. Внешние ключи включены; используется WAL, synchronous FULL, prepared statements и транзакции. Версия схемы — `PRAGMA user_version=2`. Миграция v1 → v2 сохраняет карточки и восстанавливает расписание из существующей истории. Первая миграция атомарна; более новая неизвестная версия базы блокирует запуск вместо изменения данных.

Контент сторон хранится как валидированный JSON TipTap, не как исполняемый HTML. UUID и время создания/изменения сохраняются. Изображения имеют сгенерированные имена; связи `card_images` предотвращают удаление общих фотографий при дублировании. Неиспользуемые файлы старше 24 часов очищаются при следующем запуске; задержка защищает ещё не сохранённые фото редактора. История удалённой карточки удаляется каскадно вместе с ней.

### Каталоги данных

- Windows: `%APPDATA%\MathCards\mathcards.sqlite` и `images\`.
- macOS: `~/Library/Application Support/MathCards/`.
- Точный путь показывается в настройках.
- `MATHCARDS_DATA_DIR` поддерживается только в неупакованном режиме для изоляции автоматизированных тестов.

Не копируйте открытую SQLite без WAL-файлов. Для обычного резервирования используйте ZIP-экспорт. При ручном копировании сначала полностью завершите приложение.

### Безопасность

`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, `webSecurity: true`. Нет удалённого контента, `eval`, shell-команд из renderer или произвольного файлового доступа. Preload публикует только разрешённые операции; main повторно проверяет имя операции, источник/main frame и payload через Zod. Запросы разрешений, новые окна, webview и внешняя навигация заблокированы. Production использует собственные `app://bundle` и `media://image`, CSP ограничивает скрипты, шрифты, сеть и изображения. KaTeX `trust:false`, ограничены expansion/size. Рендер текста происходит через React, HTML из карточек не исполняется.

Решения сверены с [рекомендациями Electron](https://www.electronjs.org/docs/latest/tutorial/security) и [документацией математического расширения TipTap](https://tiptap.dev/docs/editor/extensions/nodes/mathematics). Все стили и шрифты KaTeX входят в локальную production-сборку.

### Формат архива

ZIP содержит `manifest.json` (format=`mathcards`, version=1) и `images/<UUID>.<png|jpg|webp>`. В манифесте перечислены SHA-256 изображений. Импорт проверяет схему, размеры ZIP и объявленные распакованные размеры, уникальность идентификаторов/имён, ссылки, подписи форматов, контрольные суммы и белый список имён. Нет распаковки по путям, предоставленным архивом; `../`, абсолютные и неизвестные имена отклоняются.

Ограничения импорта: ZIP 256 МБ, суммарно 512 МБ после распаковки, манифест 64 МБ, изображение 20 МБ, до 20 000 карточек/изображений. Каждый импорт создаёт новые UUID для наборов, карточек, фотографий, подборок и сессий. Существующая библиотека остаётся; одинаковые названия допустимы. Ошибка откатывает транзакцию и новые файлы. Настройки включаются в манифест для справки, но не перезаписывают локальные предпочтения при объединении.

## Проверки и ограничения

Подробные реальные результаты — в [VERIFICATION.md](VERIFICATION.md). E2E создаёт отдельный временный каталог, запускает настоящее окно Electron и сохраняет скриншоты/отчёт в `test-results/`. В native file dialogs автоматизирован только выбор пути; архив создаётся и читается настоящим кодом приложения. Девять дополнительных карточек в E2E создаются через проверяемый IPC, первая — через UI. Vitest также проверяет перенос в независимую базу.

- Для интервальных повторений выбран SM-2. Альтернативный FSRS, облачная синхронизация, OCR фотографий, редактор рисования и совместное редактирование не входят в эту версию.
- Экспорт/импорт и SQLite работают в main process; крупные архивы могут ненадолго задерживать интерфейс. Текущая версия ориентирована на личную библиотеку студента, а не сотни тысяч карточек.
- Резервные копии создаются вручную. Содержимое не шифруется; защищайте профиль ОС и экспортированные ZIP обычными средствами ОС.
- Windows-установщик не подписан коммерческим сертификатом. Для публичного распространения настройте Authenticode; Windows может показывать SmartScreen для неизвестного издателя.
- Нативная проверка установки/обновления Windows и запуск Actions ожидают Windows runner. Наличие конфигурации не означает, что эти проверки уже прошли.
- Иконка исполняемого файла пока стандартная Electron; логотип внутри интерфейса собственный.

Лицензия исходного кода — MIT. Зависимости сохраняют собственные лицензии.

## Интервальные повторения в 1.1

Используются интервалы и коэффициент лёгкости из [оригинального алгоритма SM-2](https://super-memory.com/english/ol/sm2.htm). Наши три оценки соответствуют качеству 0 («Не знаю»), 3 («Сложно») и 5 («Знаю»). Первые успешные интервалы — 1 и 6 дней; последующие вычисляются с коэффициентом лёгкости, который не опускается ниже 1,3. Ошибка сбрасывает цепочку успешных повторений. Повторить неизвестные сразу можно в итогах сессии.

Практическая адаптация: в течение одних суток UTC учитывается последняя оценка карточки. Повторные тренировки и исправление оценки не раздувают интервал. История всех сессий при этом остаётся. Расписание хранится в SQLite и восстанавливается при импорте по истории оценок; новые карточки сразу попадают в очередь. Ручной выбор любых карточек работает независимо от срока.

## Подписанная Windows-сборка

Код подписи готов; для настоящей подписи издателя нужен его сертификат. Самоподписанный сертификат не выдаётся за доверенный. В GitHub **Settings → Secrets and variables → Actions** задайте `WIN_CSC_LINK` (PFX/P12 в base64) и `WIN_CSC_KEY_PASSWORD`. Не коммитьте сертификат или пароль. Запустите **Windows installer** с `signed=true`: сборка требует подпись и проверяет Authenticode у EXE и установщиков. Если сертификата нет или подпись невалидна, workflow завершается ошибкой.

Локально защищённые переменные окружения используются командой `npm run dist:win:signed`. Обычная `npm run dist:win` доступна без сертификата. Это соответствует [настройкам подписи electron-builder](https://www.electron.build/code-signing.html); подпись не обещает немедленного исчезновения предупреждений SmartScreen.

Уязвимые версии minimatch в зависимостях `app-builder-lib` и `@electron/universal` заменены точечными overrides на 11.0.8. Старые API других зависимостей не подменяются. Полный `npm audit` включён в CI.
